For computer scientists

Four research questions.
Measurable answers.

These are hypotheses, not claimed discoveries. We aim to report negative findings as carefully as positive ones.

RQ1

Does compiler feedback improve correctness?

Compare models with source alone, text errors, and structured diagnostic feedback using held-out semantic tests—not only compilation success.

RQ2

Can one interface serve several coding agents?

Control for task difficulty, tool budgets and model versions before attributing differences to the compiler–agent contract.

RQ3

Do limited capabilities improve safety?

Measure unauthorized tool use and prompt injection from malicious comments, test data and fabricated diagnostics.

RQ4

Can X serve scientific programming?

Benchmark numerical reproducibility, type/ownership behavior and development cost against Python, Rust and Julia before proposing tensor or GPU advantages.

15 October 2026 · Reproducible study protocol

Compare verified repair.
Not confident text.

Our updated technical-report draft separates developer-workflow guidance, structured compiler errors and permission-gated execution into independently testable factors.

A

Independent semantic oracles

Use held-out tests, fixed task/model/tool versions and source hashes. Compiler acceptance alone must not count as correct repair.

B

Permission and misuse controls

Measure unauthorized writes, tool requests and prompt-injection outcomes with OS-level observations—not just model self-reports.

C

Cross-language references

Python and repository-repair datasets inform experiment design but are not X benchmarks until independently ported and validated. No Hugging Face model experiment has been run.
