XCook v0.1 · X's engineering workflow

Cook carefully.
Verify everything.

XCook combines structured engineering skills with an opt-in command-line tool for developing the experimental X programming language. Humans stay in control; compiler evidence—not a model's confidence—determines what has actually passed.

Explore the workflow ↓AI & Research ↗

Experimental pre-alpha. XCook remains under private draft review in PRs #10 and #11. There is no public installer, certified agent plugin or production compiler.

The seven XCook skills

A disciplined route
from idea to evidence.

Each skill is a reviewable Markdown guide. No skill grants new shell, file or network privileges to an AI agent.

01

Orient

Check the active branch, the supported X language subset and the available Rust toolchain.

02

Design

Define semantics, alternative approaches, non-goals and explicit trust boundaries before implementation.

03

Plan

Turn the proposal into small, reversible, testable changes with clear acceptance evidence.

04

Test

Use successful programs, compile-rejection fixtures and adversarial inputs—not just happy-path samples.

05

Debug

Reproduce errors and trace the lexer, parser, type checker, IR and interpreter systematically.

06–07

Review and verify

Inspect semantics and security, then distinguish executed tests from planned, blocked or unrun checks.

Local, permission-gated CLI

Read-only
until you approve.

The zero-dependency Node.js CLI prints structured JSON for skill discovery, first-run prerequisite inspection, plans and verification previews. Its doctor command is deliberately read-only and never runs Cargo.

Running Cargo or a prebuilt X compiler requires both explicit execution flags and a trusted checkout. Even then, XCook does not deploy, merge, publish or contact model APIs.

1

Discover and plan

node xcook/bin/xcook.mjs skills and plan --goal "..." do not execute subprocesses.

2

Preview verification

verify --root . lists fixed Rust gates as planned—not passed.

3

Run only with permission

verify --root . --execute --trust-checkout deliberately runs Cargo commands. Use only in reviewed, isolated environments.

Security by construction

No surprise side effects.

A model suggestion is not authorization. XCook's default workflow refuses implicit execution and records unavailable verification as unavailable.

A

No automatic hooks

No agent auto-registration, dependency installation, background execution, telemetry or remote model traffic.

B

Constrained input

Relative .x source paths are validated against traversal and symlinks, with file size and process output limits. XCook is not an OS sandbox.

C

Evidence over claims

Blocked Rust CI stays blocked; a Node test pass does not mean the Rust compiler works. XCook reports process execution separately from compiler identity and hashes captured errors rather than exposing raw stderr. Releases require a separate human decision.

Python + C++ · Developer research

Learn across languages.
Verify before borrowing ideas.

XCook's private, unmerged Python and C++ profiles offer opt-in, syntax-focused checks. These tools do not turn X into a Python or C++ interpreter.

PY

Python parse + compilation checks

Isolated CPython parses source with ast.parse, then validates the in-memory AST using nonexecuting compile(..., "exec"). This rejects contextual syntax errors such as top-level return without executing the checked program. It is not a Python type checker, test runner, runtime bridge or sandbox.

Draft PR #11 · tested local profile
C++

Clang C++20 checks

Clang's -fsyntax-only checks C++ source without producing a linked program. The standalone profile does not configure project headers, compile native artifacts or validate ABI/runtime safety. Transitive includes and relative header resolution are not made hermetic.

Draft PR #11 · tested local profile
Permission-first workflow

No execution by default

xcook polyglot --language python|cpp --source FILE previews a check. A separately selected absolute interpreter/compiler path and both --execute and --trust-checkout are required for actual analysis. A reported syntax pass never authenticates the compiler binary.

Local evidence

Tests with precise scope

Historical draft evidence: 49/49 local Node tests. After input-snapshot hardening, 14/14 focused tests passed in an isolated reconstruction using Node, Python and Clang. Full current-branch tests, Rust compiler verification and real agent clients are pending.

Research notes and code are held in the private XCook Python/C++ draft PR #11 ↗. No Python/C++ functions or runtime have been merged into X.

Review-only engineering correction

Count bytes, not decoded characters.

Subprocess diagnostics can contain bytes that are not valid UTF-8. XCook now records raw byte counts and error-output hashes without silently replacing those bytes.

A Linux Node.js subprocess emitted four stderr bytes; the previous accounting reported eight. An isolated corrected regression passed 1/1. Three test-first cases are committed in private draft PR #11, but full XCook/Rust CI and independent tool identity remain unverified. The same draft also adds a nonexecuting CPython AST compilation check: six parse-only false positives were reproduced and rejected in 15/15 focused local subprocess controls. This is not Python execution, typing, an X-language FFI or full CI verification. No compiler release or compatibility certification is implied.

X compiler progress · review only

Conformance before compilation claims.

XCook is a developer workflow, not the X compiler. The separate Core IR draft is gaining a test-only interpreter comparison harness and a stricter entry-block verifier.

The private Core IR PR #1 contains six hand-written and 115 deterministic arithmetic test fixtures. None has passed a Rust test runner yet. The reference interpreter uses i128 arithmetic while the initial IR slice uses i32; the integer-width contract remains an open semantics decision. See the status ledger for the review boundaries.

Developer onboarding · Private review

Start by checking.
Not executing.

The draft doctor command reports project file presence without running a compiler, installing dependencies or claiming build success.

1

Run a read-only preflight

node xcook/bin/xcook.mjs doctor --root . reports the local Node version, operating system, and five expected project files as present or missing.

2

Interpret the result precisely

allFilesPresent means file presence only. executed:false and toolchainIdentityVerified:false are explicit. This is not a working installation or safety certification.

3

Separate approval from verification

Actual compiler and Cargo testing require a trusted isolated environment, a reviewed toolchain and separate explicit execution approval.

4

Evidence and limits

Five onboarding regressions passed in an earlier local reconstruction. After further bounded source-integrity hardening, an expanded local reconstruction passed 30/30 focused Node tests. The complete private checkout, Rust compiler and public installer remain unverified.

The implementation lives in unmerged private XCook PR #11. The website does not host compiler source or executable services.

Security review · 15 October 2026

A zero exit is not proof.
Source evidence matters.

Two fail-open behaviors were reproduced in XCook and corrected in private draft PR #11. These narrow defenses do not establish an OS sandbox or a trusted compiler.

SHA

Observed source changes fail closed

The path-based X check now bounds source reads and compares SHA-256 with observed file identity (including inode and change time) before and after an external tool runs. Matching content alone cannot hide the tested edit-and-restore or replacement cases. This remains an observation, not immutable-source proof; privileged changes and filesystem races are still possible.

Reviewed source · unmerged
PATH

Safer onboarding file detection

The read-only doctor now rejects symlinks in nested path components, not just the final file. This avoids false file-presence reports but is not a secure installer or a filesystem isolation guarantee.

Locally tested regression

Earlier mutation and onboarding regressions were followed by two newly reproduced same-content identity bypasses. The subsequent focused local reconstruction passed 30/30 Node tests, including three new bounded-read and identity regressions. A separate Python/C++ snapshot regression exposed a size-precheck race: before the fix, a concurrent append caused an unbounded 3,145,732-byte read despite a 1 MiB limit. The private draft now caps the actual descriptor read at the initially observed size plus one byte and rechecks file identity; four equivalent local regression cases passed, but the full private checkout and Rust tests have not run. The full private XCook suite, X Rust compiler tests, AI-agent experiments and independent security audit remain outstanding.
